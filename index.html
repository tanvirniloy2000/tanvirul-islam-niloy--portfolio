Featured projects

In-vehicle alcohol detection with Arduino

Arduino, alcohol gas sensor model, 10-bit ADC, buzzer / relay, serial monitor

Situation
Impaired driving is a major contributor to road crashes, and a check that does not depend on the driver’s honesty has to work on cheap, noisy hardware.
Task
Build a sensing chain that samples breath alcohol, compares it with a calibrated threshold and drives an alert or cut-off output, without tripping on sensor noise.
Action
Read the sensor through the Arduino’s analog input and measured clean-air and alcohol-exposure baselines to pick the threshold. Added a warm-up period, sample averaging and hysteresis to reject transient spikes. Isolated faults bottom-up: power rails, sensor warm-up, raw ADC counts on the serial monitor, decision logic, output stage.
Result
To not drive by alchoholic driver for this project , Improving this project , working on .

Network lens. Fault isolation here is the same layered method as network troubleshooting. Raw ADC counts are the equivalent of interface counters, and a baud-rate mismatch on the serial link produces garbage the way a duplex mismatch produces CRC errors.

Mobile health solution for breast cancer detection (deep learning)

Python, [TensorFlow / PyTorch], CNN [architecture or backbone], [mobile framework]

Situation
Access to specialist screening is limited, and a phone-based triage aid could widen early detection if it is accurate and fast enough to use.
Task
Train an image classifier judged on clinically meaningful metrics and deliver its predictions through a mobile app.
Action
Prepared the dataset with resizing, normalisation and augmentation, and split train, validation and test sets by patient to avoid leakage. Trained the CNN and evaluated recall, precision, F1 and ROC-AUC rather than accuracy alone. Packaged the model for on-device inference / REST API.
Result
Report sensitivity, specificity and AUC on the held-out test set, plus app latency.

Network lens. If inference runs remotely, the design depends on upload payload size, TLS handshake cost and round-trip time over weak mobile links. On-device inference trades model size for independence from the network. I can defend either choice with numbers.

Campus-style VLAN lab in progress

Cisco Packet Tracer or GNS3, Cisco IOS

Topology
One router, two access switches and an 802.1Q trunk between them. VLAN 10 (Staff, 192.168.10.0/26), VLAN 20 (Guest, 192.168.20.0/26) and VLAN 99 (management).
Build
Router-on-a-stick sub-interfaces for inter-VLAN routing, a DHCP pool per VLAN, an extended ACL that blocks Guest from Staff, NAT overload to the upstream link and port security on access ports.
Proof
Verified with show vlan brief, show interfaces trunk, show ip route and ACL hit counters. Configs and topology will be published on GitHub.
